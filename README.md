# slipway platform `slipway` — dev (integranz)

The one cloud foundation every repository of the organisation deploys through (`options.platform_scope: shared` in slipway). Generated by `node <plugin>/scripts/platform.cjs render --config platform.yaml --out .`; change `platform.yaml` and re-render instead of hand-editing. No subscription or tenant id is committed here.

## What it provides
| Resource | Name | Created by |
|---|---|---|
| Resource group (apps of every repository deploy into it) | `rg-slipway-dev` | `setup-platform.sh` |
| Terraform state storage (Entra-only auth) | `rg-slipway-tfstate` / `stslipwaytf` / `tfstate` | `setup-platform.sh` |
| CI/CD identity (user-assigned managed identity, flexible federated credentials for `repo:integranz/*`) | `id-slipway-cicd-dev` | `setup-platform.sh` |
| Registry | `acrslipwaydev` | `infra/foundation` |
| Key vault (RBAC, per-app per-secret roles) | `kv-slipway-dev` | `infra/foundation` |
| Container Apps environment | `cae-slipway-dev` | `infra/foundation` |
| Log Analytics | `log-slipway-dev` | `infra/foundation` |
| Organisation secrets `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` | — | `setup-platform.sh --set-github-secrets` |

## Setting it up (owner, once; every step is idempotent)
1. `az login && az account set --subscription <name>`; `gh auth login` with an organisation owner account.
2. `bash setup-platform.sh` (dry run) → read → `bash setup-platform.sh --apply --set-github-secrets`: resource groups, state storage, the CI/CD identity with its four flexible federated credentials (CI on `main` and CD on environment `dev`, immutable and classic subject forms), its roles (Contributor on the resource group, Storage Blob Data Contributor on the state container), and the `AZURE_*` organisation secrets.
3. Foundation: `export ARM_SUBSCRIPTION_ID=$(az account show --query id -o tsv)`, then `terraform -chdir=infra/foundation init`, `plan -out=tfplan.dev`, read it, `apply tfplan.dev`.
4. Per-app identities (the default on the shared platform) need the CI/CD identity to create role assignments, but only two roles: a subscription **Owner** runs `bash setup-platform.sh --grant-per-app-roles` (Role Based Access Control Administrator on the registry limited to `AcrPull`, Key Vault Data Access Administrator on the vault limited to `Key Vault Secrets User`, both with ABAC conditions; the script prints the exact commands when it cannot run them).
5. Publish the organisation template for the onboarding poller: `gh variable set ONBOARD_ANSWERS_TEMPLATE -R integranz/slipway --body "$(grep -v '^#' org-defaults.yaml)"`. New repositories then join this platform automatically.
6. Organisation secrets the generated workflows read: `DOCKERHUB_TOKEN` + variable `DOCKERHUB_USERNAME` (hardened base images), `JIRA_API_TOKEN` + variable `JIRA_EMAIL` (tracker): `gh secret set <NAME> --org integranz --visibility all --body "$(pbpaste)"`.

## What stays per repository
The onboarding pull request (reviewed and merged by a human), the deployment environment with its reviewer (created by the poller), the Key Vault secret **values** (`az keyvault secret set --vault-name kv-slipway-dev --name <project>-<name> …`, listed in each repository's `.slipway/SETUP.md`), and the CD approval.

## Trade-offs
Every repository's CD runs as the same identity with Contributor on `rg-slipway-dev`: a plan can touch another repository's resources; the plan shown at the environment approval is the control. The Container Apps environment is shared: one network and one default domain; container apps are named `<project>-<app>`.
